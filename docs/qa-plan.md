# SNOWCUB RUN 재구축 검증 계획

## 1. 검증 목표

새 게임은 이전 소스를 보존한 별도 구현이다. 검증의 최우선 목표는 다음 네 가지다.

1. 입력과 상태 전환이 언제나 같은 규칙으로 동작한다.
2. 한 번의 충돌은 체력 1칸만 줄이고, 체력 소진 전에는 진행 위치를 되감지 않는다.
3. 게임을 멈추거나 다시 시작하거나 체크포인트에서 부활해도 화면과 내부 상태가 어긋나지 않는다.
4. 3단계 보스는 백사자와 안전 거리를 유지하고, 발이 같은 지면선에 놓이며, 패배 시 아래로 떨어지지 않고 제자리에서 투명해진다.

불과 얼음은 공격의 색·입자·효과음만 달라야 한다. 이동 속도, 피해량, 공격 범위와 재사용 시간은 동일 입력에서 완전히 같아야 한다.

## 2. 테스트 층

### A. 순수 게임 규칙 테스트

브라우저와 그림 없이 `초기 상태 생성 → 입력 적용 → 시간 진행 → 상태 비교`만 수행한다. 난수는 고정된 seed 또는 주입된 난수 함수로 통제한다. 120Hz 입력으로 같은 시나리오를 두 번 실행했을 때 같은 결과가 나와야 한다.

필수 범위:

- 시작 전, 실행 중, 일시정지, 피격 후, 부활 대기, 스테이지 완료, 보스전, 승리의 상태 전환
- 자동 달리기와 스테이지별 속도 상승
- 1단·2단 점프, 세 번째 점프 거절, 착지 후 점프 횟수 초기화
- 공격 재사용 시간과 적·보스 명중
- 장애물·적·투사체 충돌, 무적 시간, 체력과 점수 변화
- 코인·먹이 획득, 점프 최고점에 맞춘 배치 가능 높이
- 200m 체크포인트 저장, 체력 0일 때만 최근 체크포인트 부활
- 3단계 보스 등장·공격·피격·퇴장·최종 승리
- 큰 프레임 지연, 잘못된 시간값, 화면 비활성화 후 복귀

### B. 화면과 조작 연결 테스트

실제 브라우저에서 키보드와 화면 버튼을 사용한다.

- 시작 화면에서 불/얼음 선택 후 게임이 시작되는가
- 점수는 상단 중앙, 체력·스테이지·거리·체크포인트는 서로 겹치지 않는가
- 조작 설명이 실제 배치와 동일한 순서인가: `점프 = Space/↑/왼쪽 버튼`, `공격 = X/오른쪽 버튼`
- Space를 빠르게 두 번 눌렀을 때 2단 점프가 되고, 누르고 있기나 키 반복으로 3회 이상 점프하지 않는가
- P/Escape/일시정지 버튼이 같은 동작을 하는가
- 일시정지 화면의 `계속하기`는 정확히 이전 상태로, `처음부터 다시 하기`는 불·얼음 선택 화면으로 이동하는가
- 창을 벗어나거나 탭을 숨기면 자동 일시정지되는가
- 캔버스/화면 버튼을 누를 때 페이지가 스크롤되거나 확대되지 않는가

### C. 시각 회귀 테스트

고정된 게임 상태를 주입해 데스크톱 1440×900, 태블릿 768×1024, 모바일 390×844와 320×568에서 이미지를 남긴다.

필수 장면:

- 시작 화면 불/얼음 선택
- 1단계 사막, 2단계 사원, 3단계 정글
- 달리기 6프레임 중 앞발·뒷발이 반대 위상인 두 프레임
- 1단 점프 최고점, 2단 점프 최고점과 아이템 중심 높이
- 불 공격, 얼음 공격, 피격 무적 깜빡임
- 일시정지 화면
- 보스 시작, 최근접 위치, 보스 패배 직전(알파 약 0.5), 보스 소멸 후 승리

보스의 `발 기준선`은 백사자의 발 기준선과 같은 화면 y값이어야 한다(허용 오차 2px). 살아 있는 보스의 왼쪽 충돌 경계는 백사자 오른쪽 충돌 경계에서 최소 150px 떨어져야 한다. 퇴장 중 보스 y값과 발 기준선은 고정되고, 알파만 1→0으로 감소해야 한다.

### D. 오디오 검증

브라우저 자동재생 제한 때문에 첫 사용자 입력 전에는 소리가 없어도 정상이다. 불/얼음 선택 버튼을 누른 직후 오디오 문맥이 활성 상태인지 확인한다.

이벤트별 서로 다른 소리:

- 점프
- 코인 획득
- 먹이 획득
- 일반 피격
- 적 격파: 불 선택 시 연소 질감, 얼음 선택 시 빙결 파열 질감
- 보스 투사체 발사·보스 피격·보스 격파
- 체크포인트·스테이지 완료·승리

효과음은 BGM보다 순간 최대 음량이 크되 계속 울리지 않아야 한다. 음소거는 BGM과 효과음 모두를 멈추며, 해제 후 이중 재생되지 않아야 한다. 일시정지 중 BGM 처리 방식은 하나로 고정한다(권장: 낮은 음량으로 유지하거나 완전 정지 중 하나). `감소된 움직임` 설정은 시각 효과만 줄이고 소리를 바꾸지 않는다.

### E. 접근성과 모바일

- 모든 버튼은 키보드 Tab으로 도달하고 Enter/Space로 작동한다.
- 포커스 표시가 배경과 3:1 이상 대비된다.
- 아이콘만 있는 버튼에는 한국어 접근성 이름이 있다.
- 체력은 색/하트만이 아니라 `체력 4/5`처럼 읽을 수 있다.
- 점수·체력 변화는 매 프레임 읽히지 않고 의미 있는 변화만 알린다.
- 모바일 조작 버튼은 최소 44×44px이며 서로 겹치지 않는다.
- 200% 확대, 320px 폭에서 가로 스크롤과 잘린 주요 버튼이 없다.
- `prefers-reduced-motion` 또는 게임 설정을 켜면 화면 흔들림·입자·빠른 깜빡임이 줄어든다.
- 백그라운드 이미지가 없어도 조작, 장애물 식별, HUD 읽기가 가능하다.

## 3. 통과 기준

- P0/P1 회귀 사례 100% 통과
- 순수 규칙 테스트 전부 통과, 브라우저 콘솔 오류 0건
- 불/얼음 동일 입력 10,000 tick 비교에서 게임 규칙 상태가 동일
- 데스크톱 및 모바일 주요 흐름: 시작 → 2단 점프 → 코인/먹이 → 피격 → 체크포인트 부활 → 일시정지/계속 → 재시작 → 3단계 보스 → 승리 통과
- 보스 y/발 기준선 고정과 거리 제한을 수치 테스트와 화면 이미지에서 모두 확인
- Chrome 외 Safari 또는 Firefox 한 종류에서 핵심 조작 수동 확인

## 4. 권장 실행 순서

1. 순수 규칙 테스트를 실행한다.
2. P0 회귀 사례만 먼저 브라우저에서 재현한다.
3. 전체 키보드·터치 흐름을 확인한다.
4. 고정 상태의 시각 회귀 이미지를 비교한다.
5. 실제 사용자 입력으로 오디오를 활성화하고 각 이벤트 소리를 확인한다.
6. 320px 모바일과 `감소된 움직임` 설정을 마지막으로 확인한다.

## 5. 출시를 막는 조건

- 피격 1회로 시작 화면 또는 스테이지 시작점으로 이동함
- 체력 1~4에서 체크포인트로 되감기거나 체력 0인데 부활하지 않음
- 일시정지 중 거리·적·쿨다운·보스 타이머가 진행됨
- 2단 점프가 안 되거나 3단 이상 점프 가능
- 처음부터 다시 하기가 속성 선택 화면이 아닌 실행 화면으로 이동
- 적 격파 효과음 누락 또는 불/얼음 소리가 같음
- 보스가 백사자와 겹치거나 발 기준선이 다르거나 패배 시 y값이 증가함
- 키보드나 터치 중 하나로 핵심 플레이를 완료할 수 없음
