## 발견 문제

### P0 — 모바일에서 시작 화면·HUD·게임 오른쪽이 잘림

관련 위치: `dist/styles.css:64`, `dist/styles.css:155`, `dist/styles.css:177`

재현:

1. 화면 폭을 320px 또는 390px로 설정한다.
2. 첫 화면에서 불/얼음 선택 영역과 점수 HUD를 본다.
3. 오른쪽의 얼음 카드, 문장, 점수와 게임 화면 일부가 잘린 것을 확인한다.

측정값(320×568):

- `.arcade` 실제 안쪽 폭: 298px
- `.viewport` 계산 폭: 520px
- 시작 버튼: x=44px, 폭=454px(오른쪽 끝 498px)
- 점수 패널 중심: x=457px
- 문서 전체의 가로 스크롤은 320px로 막혀 있어 잘린 부분으로 이동할 수도 없음

원인:

`aspect-ratio: 4 / 3`인 요소에 `min-height: 360px`, 다시 `390px`을 주면서 브라우저가 최소 높이를 맞추기 위해 폭을 480~520px로 확장한다. 바깥 `.arcade`가 `overflow: hidden`이므로 초과 부분은 숨겨진다.

권고 수정:

- 모바일 `.viewport`에 `width: 100%`를 명시하고, 폭을 늘리는 `min-height`를 제거한다.
- 모바일에서 원하는 높이는 컨테이너 폭으로부터 계산하거나, 고정 폭 안에서 레터박스/별도 모바일 종횡비를 사용한다.
- 수정 후 320px과 390px에서 `.viewport.clientWidth <= .arcade.clientWidth`, 점수 중심이 화면 중앙 ±8px, 두 속성 카드와 시작 버튼 전체 노출을 자동 검증한다.

증거 이미지: `day06/agent-work/rebuild-2026-09-18/qa/mobile-320-ready.png`

### P1 — 곰 발이 지면 아래로 7px 잠기고 백사자와 기준선이 다름

관련 위치: `dist/js/art.js:172-196`

재현:

1. 3단계 보스 고정 장면을 렌더링한다.
2. 곰 스프라이트 4개 프레임과 백사자 달리기 프레임의 불투명 픽셀 최하단을 측정한다.

측정:

- 논리 지면: y=396
- 곰 4프레임 모두 보이는 발 최하단: y=403
- 백사자 달리기 0/1프레임 발 최하단: y≈392.6~392.9
- 가장 안정적인 달리기 프레임과 곰 사이 기준선 차이: 약 10px

기능 상태의 `boss.y`는 패배 전후로 고정되어 아래로 떨어지는 버그는 해결되었다. 그러나 렌더링할 때 `GROUND - 239` 위치에 높이 246px로 그려 원본 프레임의 발이 지면 아래로 내려간다.

권고 수정:

- 곰 프레임의 `footOffsetY`를 명시해 실제 발 최하단이 GROUND에 오도록 약 7px 위로 올린다.
- 백사자 6개 프레임에도 프레임별 발 기준선 보정값을 둔다. 달리기 자세로 발이 들린 장면과 스프라이트 전체가 위로 흔들리는 현상을 구분한다.
- 정적 픽셀 검사에서 곰과 백사자의 기준선 차이를 2px 이하로 유지한다.

증거 이미지: `day06/agent-work/rebuild-2026-09-18/qa/boss-alignment.png`

### P1 — 모바일 점프·공격 버튼의 좌우 위치가 설명과 반대

관련 위치: `dist/index.html:95-103`

재현:

1. 화면 폭을 390px 이하로 설정한다.
2. 게임 위 설명과 아래 터치 버튼을 비교한다.

현재:

- 설명: 점프는 왼쪽, 공격은 오른쪽
- 터치 버튼: 공격은 왼쪽, 점프는 오른쪽

과거에 “점프와 공격 설명 위치가 헷갈린다”는 피드백이 있었으므로 위치 불일치는 재발 가능성이 높다.

권고 수정:

터치 버튼의 DOM 순서를 `점프 → 공격`으로 바꾸거나 CSS 순서를 조정해 설명과 동일하게 맞춘다. 접근성 읽기 순서도 시각 순서와 같아야 한다.

### P2 — 체크포인트 간격 계약 확인 필요

관련 위치: `dist/js/core.js:9`

검증 계약은 200m 간격을 기준으로 작성했으나 통합본은 250m를 사용한다. 사용자에게 간격이 직접 확정된 것이 아니라면 250m도 기능 오류는 아니지만, 총괄 기획에서 하나로 확정하고 화면 설명·테스트와 일치시켜야 한다.

### P2 — 회귀 테스트 범위가 계약보다 짧음

불/얼음 동일성 테스트는 1,800 tick이며 검증 계약의 10,000 tick보다 짧다. 코드 검토상 속성별 기계 성능 분기는 보이지 않았으나, 장시간 스테이지/보스까지 포함한 동일성 비교와 이벤트 1회성 테스트를 추가하는 것이 안전하다.

추가 권고 테스트:

- 적 격파 시 `enemy-defeated`가 정확히 한 번 발생하고 `detail.element`가 전달되는지
- 보스 투사체 여러 개가 같은 프레임에 겹쳐도 체력이 1만 감소하는지
- 320px/390px에서 속성 카드·시작 버튼·점수·거리·터치 버튼 bounding box가 컨테이너 안에 있는지
- 보스/백사자 스프라이트 불투명 픽셀의 발 기준선 차이가 2px 이하인지

### P3 — favicon 404

브라우저에서 `/favicon.ico`가 없다는 404가 새로고침마다 발생했다. 게임 실행에는 영향이 없지만 콘솔 오류 0건 기준을 충족하려면 favicon을 제공하거나 명시적 아이콘 링크를 추가한다.

## 통과한 핵심 회귀 항목

- 피격 1회는 체력 1만 감소하고 진행 거리를 초기화하지 않음
- 체력 0에서만 최근 체크포인트와 저장 점수로 부활
- 불/얼음의 이동·점프·공격 성능 동일
- 2단 점프 허용, 세 번째 점프 거절, 착지 후 초기화
- 일시정지 중 거리·물리·쿨다운·보스 타이머 정지
- 아이템은 지면 달리기로 획득되지 않고 점프 동선에서 획득 가능
- 공격으로 하이에나/유령은 제거되지만 돌·문턱은 제거되지 않음
- 1→3단계 속도 상승과 1·2단계 거리 클리어
- 곰이 백사자와 150px 이상 거리를 유지
- 곰 패배 시 물리 y는 고정되고 알파만 줄어든 뒤 승리
- 처음부터 다시 하기는 불/얼음 선택 화면으로 이동하고 진행 상태 초기화
- 잘못된 프레임 시간으로 상태가 오염되지 않음

## 출시 판단

현재 버전은 **데스크톱 시연용으로는 핵심 플레이가 가능**하다. 하지만 모바일 사용자는 첫 화면부터 오른쪽 절반을 볼 수 없고 점수도 사라지므로 공개 배포 기준으로는 출시할 수 없다. 최소한 P0 모바일 잘림과 P1 보스 발 기준선·조작 위치를 수정한 뒤 320px/390px 브라우저 회귀를 다시 통과해야 출시 가능하다.
