# SNOWCUB RUN — 디자인·자산 규격

## 1. 시각 목표

- 핵심 감성은 1990년대 16-bit 런 게임의 선명한 픽셀 아트와 다층 스크롤입니다.
- 주인공은 규여운 아기 백사자이며, 서 있는 그림 대신 앞발·뒷발이 교차하는 6프레임 달리기를 사용합니다.
- 불과 얼음은 성능과 판정이 같고, 공격 색·입자·소리만 다릅니다.
- 배경과 적은 주인공보다 채도와 선 두께를 낮춰 조작 대상이 먼저 보이게 합니다.

## 2. 캔버스와 픽셀 규칙

| 항목 | 규격 |
|---|---|
| 논리 캔버스 | `960 × 480` |
| 발 접지선 | `groundY = 382` (모든 지상 캐릭터 공통) |
| 백사자 표시 크기 | `144 × 144px`, 가로를 별도로 늘리지 않음 |
| 하이에나 표시 크기 | `184 × 160px`, 백사자보다 18~28% 큰 실루엣 |
| 유령 표시 크기 | `126 × 126px`, 접지선에서 54~92px 부유 |
| 거대 곰 표시 크기 | 원본 크롭 `527 × 370` → `350 × 246px` |
| 렌더링 | `imageSmoothingEnabled = false`, x/y는 반올림해 정수로 그림 |
| 반응형 | 캔버스 내부 좌표는 고정, CSS로 전체를 동일 비율 확대·축소 |

화면이 작아져도 종횡비를 바꾸지 않습니다. 세로 700px 이하에서는 조작 버튼을 캔버스 아래로 보내고, 버튼의 최소 높이는 48px로 유지합니다.

## 3. 백사자 스프라이트

원본 `white-lion-run-spritesheet-2026-09-10-v01.png`은 `1536 × 1024`, 3열×2행이며 프레임 하나는 `512 × 512`입니다.

- 프레임 순서: `0 발 뻗음 → 1 모음 → 2 체공 → 3 반대발 뻗음 → 4 모음 → 5 착지`.
- 프레임 속도: 1단계 9fps, 2단계 10fps, 3단계 11fps. 게임 속도와 동기화하되 14fps를 넘지 않습니다.
- 원본의 체커보드 무늬는 투명이 아닙니다. 로드 시 오프스크린 캔버스에서 `RGB 최대-최소 ≤ 8`, `R 100~228`인 중성 회색만 alpha 0으로 바꾸고, 변환된 캔버스를 매 프레임 재사용합니다. 이 처리가 달릴 때 배경에 생기는 점선 무늬를 없앵니다.
- 각 프레임의 원본 여백이 달라 발이 튀어 보이므로, `144px` 표시 기준 y 보정은 `[0, 0, 14, 15, 15, 17]px`를 사용합니다. 모든 프레임의 가장 낮은 앞발/뒷발이 `groundY`에 닿게 합니다.
- 충돌 영역은 그림 전체가 아니라 몸통 기준 `x + 31, y + 35, 82 × 91px`를 사용합니다. 꼬리와 털은 판정에서 제외합니다.
- 점프 시 상승은 2번, 체공은 5번, 하강은 3번 프레임을 고정 사용합니다. 수직 위치만 포물선으로 바꾸어 가로로 늘어지지 않게 합니다.
- 공격 동안 몸은 2° 이내로만 앞으로 기울이고, 공격 이펙트가 입 앞 `x + 112, y + 57`에서 시작합니다.

## 4. 적·보스 규격

### 하이에나와 유령

`villain-spritesheet-2026-09-10-v01.png`은 `1536 × 1024`, 4열×2행, 프레임 `384 × 512`입니다. 1행은 하이에나, 2행은 유령입니다.

- 원본의 마젠타 배경은 `R > 215 && G < 90 && B > 175`일 때 alpha 0으로 변환합니다.
- 하이에나 4프레임은 9fps로 재생하고, 표시 크기는 184×160px로 해 백사자보다 분명히 크게 보입니다. 충돌 영역은 112×76px입니다.
- 유령은 7fps와 ±6px 사인 파 부유 동작을 겹칩합니다. 충돌 영역은 중앙 74×84px입니다.

### 거대 곰 최종 보스

`giant-bear-boss-spritesheet-2026-09-11-v01.png`은 `2172 × 724`, 4열×1행, 프레임 `543 × 724`입니다. 하단 투명 여백이 커서 전체 프레임을 그리면 발이 뜨는 문제가 생깁니다.

- 각 프레임에서 소스 크롭을 `sx = frame * 543 + 8`, `sy = 150`, `sw = 527`, `sh = 370`으로 통일합니다.
- 위 크롭을 `350 × 246px`로 그립니다. 원본의 형태를 거의 유지하면서 백사자의 2.3배 크기가 됩니다.
- 발 접지선은 크롭 아래에서 7px 위입니다. 대상 사각형을 `dy = groundY - 239`에 놓으면 곰과 백사자의 발이 같은 땅에 닿습니다.
- 곰의 목표 x는 650~735 범위로 유지합니다. 충전 연출 시에도 560 미만으로 오지 않아 백사자와 최소 260px 간격을 유지합니다.
- 패배 시 y, 속도, 중력은 절대 바꾸지 않습니다. 0.9초 동안 `globalAlpha 1 → 0`, 색상 채도 100% → 0%, 소형 불똥/얼음 입자 8~12개만 남겨 **제자리에서 서서히 사라지게** 합니다.

## 5. 3개 스테이지 배경

| 스테이지 | 원본 | 분위기 | 추가 레이어 | 추천 포그 |
|---|---|---|---|---|
| 1 사막 | 2048×768 | 하늘색·황금·코럴, 밝은 시작 | 먼 구름 0.05x, 산 0.13x, 유적 0.28x | `rgba(255,181,84,.06)` |
| 2 신전 | 1983×793 | 버건디·황금, 어둡고 비밀스러움 | 기둥 0.18x, 상형 0.34x, 불꽃 0.55x | `rgba(61,8,38,.14)` |
| 3 정글 | 2079×756 | 초록·주황, 생명력과 위기 | 먼 화산 0.08x, 나무 0.22x, 앞쪽 풀 0.48x | `rgba(16,64,35,.08)` |

- 배경은 캔버스 960×382 영역을 `cover` 하되 종횡비를 유지합니다. 지평선이 접지선과 겹치지 않게 소스 y 크롭을 스테이지별로 보정합니다.
- 왼쪽→오른쪽으로 원본과 좌우반전본을 교대 배치해 직선 타일 경계를 줄입니다. 16px 교차 페이드를 사용해 끊김을 숨깁니다.
- 땅은 배경 이미지와 별도의 98px 전경 타일로 덮어, 사자·적·곰이 모두 하나의 `groundY` 위에 서게 합니다.

## 6. 장애물·수집물·공격 연출

- 돌·문턱·가시는 점프로만 회피하도록 허리 아래 충돌 영역을 사용합니다.
- 하이에나·유령은 공격으로 제거합니다. 장애물과 적의 실루엣과 색을 다르게 해 반응 방식을 눈으로 알 수 있게 합니다.
- 코인·먹이는 1차 점프의 최고점 근처인 `groundY - 158~172px`에 배치합니다. 신호처럼 3개를 곡선으로 배치하면 2단 점프를 자연스럽게 학습합니다.
- 불 공격: 0~90ms 작은 화염 3개 → 90~310ms 화염 혜성 전진 → 310~500ms 불꽃 12개 확산. 핵심색 `#ff5a36`, 중앙 `#ffe77a`, 연기 `#612a2a`.
- 얼음 공격: 0~80ms 청백색 번쩍임 → 80~320ms 얼음 창 3개 전진 → 320~520ms 육각 결정 10개 분해. 핵심색 `#43d9ff`, 하이라이트 `#efffff`, 그림자 `#315caa`.
- 공격 판정은 두 속성 모두 입 앞 32px에서 시작하는 `190 × 82px`, 110~360ms 구간으로 고정합니다.
- `prefers-reduced-motion` 또는 설정의 모션 줄이기가 활성화되면 배경 패럭스, 화면 흔들림, 입자 수를 50% 이상 줄이되 조작 판정과 속도는 유지합니다.

## 8. 구현 검수 항목

- 백사자가 달릴 때 배경 체커/점선이 나타나지 않음.
- 달리기 6프레임에서 발 접지선이 2px 이상 튀지 않음.
- 백사자를 144×144로 그려 가로로 길어 보이지 않음.
- 하이에나가 백사자보다 크고, 대신 충돌 판정은 털/꼬리를 제외해 공정함.
- 곰의 발이 `groundY`에 맞고, 패배 시 y가 바뀌지 않은 채 alpha로만 사라짐.
- 불·얼음 공격은 보기에는 다르지만 범위·지속시간·피해는 같음.
- 휴대폰에서 화면이 늘어지지 않고, 조작 버튼이 48px 이상임.
